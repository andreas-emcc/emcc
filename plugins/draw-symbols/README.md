# draw-symbols

Place, edit and move single-point APP-6 symbols (`core.symbol`) on the map (brief: `docs/plugins/briefs/draw-symbols.md`, tasks T-023, T-042, T-054, T-066, T-085, T-118, T-120, T-103, T-130, T-132, T-139, T-150, T-165 and T-156). Web part only. Built against web SDK 1.6.0 (symbol palettes, CR-0041 part G; a data type brings its field sets, CR-0038; field sets, ADR-0050; vessel symbols, ADR-0047; relations, ADR-0051; the layer lock, ADR-0042; the `signal` of the map interactions, CR-0020; workspaces, ADR-0039; declared fields, ADR-0038) and data model 1.5.0 (`sdkVersion` `^1.6.0`). **From M2 the map view selects and the shell's shared Delete deletes** (ADR-0032): this plugin has no click selection, no Escape handling of its own and no Delete.

## What it does

Two panels (`ctx.ui.addPanel`, default panes: Symbols left, Symbol properties right (M4), ADR-0031; the user may move them to another pane, and they work in every pane), and one object action:

**"Symbols"** (panel id `draw-symbols-symbols`; default pane **left** since M4, T-108)
- A grid of the `SymbolService` catalog **by category** (M4, T-118), drawn as symbol images at `pickerSymbolSize`, with the standard identity and echelon to combine them with. A preview shows the resulting SIDC.
- **Category:** a select with one entry per symbol set of the catalog (`CatalogEntry.symbolSet`), in the catalog's order: Land unit, Land equipment, Land installation, Air, Air missile, Space, Sea surface, Sea subsurface, Mine warfare and the five Signals intelligence sets. The names are this plugin's (`src/categories.ts`); a set it has no name for is listed by its code. The grid shows the chosen category's entries only, so a name such as "Radar" is not repeated. The category is kept in this browser (`localStorage` key `draw-symbols.category`) and shown again on the next visit; with none kept, or one the catalog does not have, the first category is shown.
- **Echelon** applies to land units (symbol set `10`) only, because the other sets use digits 9 and 10 for other things. For any other category the select is not shown and a new symbol gets `00`; the choice made for land units is still there when the user goes back.
- **Data type:** a select with the available data types (`ctx.dataTypes`) that users choose (`choosableDataTypes`: no route or detection, see "A data type brings its sets") by display name, `core.general` first. New symbols get the chosen one. The choice is kept in this browser (`localStorage` key `draw-symbols.dataType`) and wins on the next visit. Without a kept choice, or when the kept data type is not available any more, the setting `dataType` applies; if that is not available either, `core.general`.
- *Advanced:* a SIDC can be typed instead. `SymbolService.validate` checks it for the configured standard; an invalid one shows the reason and cannot be placed. Choosing a catalog symbol clears the typed one.
- **Place on map** starts placing: every click on the map sends a create for the chosen symbol, until **Stop placing** or Escape. **Two clicks less than 250 ms apart are one placement** (a double-click): the first click's point is used and the second click is dropped. The time is measured from the last symbol that was placed, and each placing session starts fresh. It is disabled with the hint "Select or create a layer in the layer panel" when the active layer does not exist, and with the hint "You may not edit objects" without `objects.edit`.
- The create has a new id (`ctx.newId()`, UUID v7), the active layer, `defaultLabel`, the point clicked (lon/lat, no altitude), the configured standard, the chosen `dataType` and `dataSource` `manual`.

**"Symbol properties"** (panel id `draw-symbols-properties`) for the selected symbol. It follows the map view's selection (shared by all plugins): **exactly one `core.symbol` selected** shows its fields; **several objects** show "N objects selected" and no fields; **one object of another type** (a shape) shows nothing; none shows "Select a symbol on the map.":
- Preview; identity, echelon (land units only; for any other symbol set it is hidden and the symbol keeps its own digits), category and entity (choices from the catalog; the entity select lists the entities of the symbol's own category; a change of category gives the first entity of the new one and no echelon); SIDC; name; the text modifiers `uniqueDesignation`, `higherFormation` and `additionalInformation`; position in the user's coordinate format, editable; heading, speed and altitude (below) (`CoordinateService.format` and `parse`); layer; **data type** (a select, one update when changed). Read only: data source, security label, version, last modified (when, and by which plugin or user).
- A data type that is not available any more (its plugin was removed) is shown in the select as "`<id>` (not available)" and is kept by every update until the user picks an available one.
- Objects from other sources (e.g. `cot`) can be edited like drawn ones; their data source is shown and never changed. The next report from that source may overwrite the edit.
- A text field commits on Enter or when it loses focus, never on a keystroke. Escape drops what was typed. A select commits when changed.
- A `core.symbol` that is not a point is shown read only (type, layer, data type, data source, label, version, last change).
- **A symbol this plugin does not hold yet** (selected by the map view or in `object-list`, chosen with Edit, or one that has just left its area) is **read by id** (`ctx.objects.get`) while the area round it is subscribed (see "The live picture"): "The selected object has not arrived yet." while it is read, "The selected object no longer exists." when it is gone. While it is only read, and not held, the plugin reads it again before **every** commit, so the update is based on the newest version; the panel then shows the state the server answered with. If the read fails, the user gets "Could not read the symbol, try again." (and a "Try again" button when the panel could not read it), and nothing is sent. A symbol that is **outside the map view's visible area** (the plugin tests its position against `MapView.viewport.visibleArea`, also when the view moves) shows the note "Not in view", and cannot be dragged. The plugin never moves the map: the user brings the symbol into view with the map view's Centre on or Zoom to.

**The object action Edit** (`ctx.actions.addObjectAction`: id `edit`, group `edit`, for `type` `core.symbol`, one object only, needs `objects.edit`). It selects the symbol (the shared selection) and brings the properties panel into view (`show()`: expanded, in whichever pane it is). The shell's menu shows it on the map and in `object-list`'s rows; the shell hides it without the permission, for a selection of several and for other kinds of object.

**Without `objects.edit`** (`ctx.user`, ADR-0022): the panels are **read only** with the hint "You may not edit objects". In the properties panel every field and select and dragging are off (the shell's Delete is hidden by the shell); in the Symbols panel only placing is off (the picker stays usable: it changes only the preview and the kept data type choice). Selecting and viewing still work. The controller also refuses an edit that gets past the panel, with a warning. The server checks anyway: a `PERMISSION_DENIED` rejection is a notification like any other. The no-login user has every permission.

**On the map**
- Selecting is the map view's: a click, Ctrl or Cmd+click and a box (ADR-0032). This plugin only reads and follows the selection; it sends none of its own.
- Dragging the selected symbol (`MapView.dragObject`) sends one update with the drop point. A press and drag starts on the symbol only; a click still selects. **The drag is armed the moment exactly one object is selected**, before the plugin has read it (the map view gives only an id, and a drag that began right after the click would be lost: criterion 3 of the ITA flaked on it). It is armed **once per selection**, so that it never takes the map again and again from another plugin's drag. Once the object is known, a symbol in the map view's visible area keeps it; for an object that is not an editable symbol, or a symbol out of view, the plugin **ends its drag with its `signal`** (T-066, CR-0020), so that `draw-shapes`' drag can take over (if that one has already replaced it, the abort changes nothing). A drop that came before the object was known to be such an object is ignored (no request, no notice); a symbol dragged at once still moves.

**How changes are sent**
- An update sends the **complete core content** of the latest state (`type`, `dataType`, `dataSource`, `time`, `layerId`, `geometry`, `symbol`, `style`, `properties`, `label`) with only the edited part changed, and `baseVersion` = that state's version. `dataSource` is always the stored one (model rule 14). Anything the plugin does not edit (`style`, `description`, `direction`, `speed`, `time`, an altitude) is sent back as it was. **`extensions` is never sent**, so the object store keeps every plugin's extensions (model README, rule 5).
- Nothing is applied locally before the server answers. The panel follows the live picture; the applied outcome of our own request is also used at once, so two quick edits of one object do not overwrite each other.
- **One request at a time per object:** later edits wait for the earlier ones and are built from the state the earlier one produced. At most 20 requests wait at once in a browser (the server refuses more than 100); one more gives a notification. A button is disabled while its object has a request waiting.
- **A refusal** is a notification with the server's reason and code; text fields keep what was typed. Editing an object someone else deleted first gives a warning, not an error.
- **No answer (`OutcomeUnknownError`):** a create is sent again with the same id (if the first arrived, `ENTITY_EXISTS` means it is there and nothing is shown), and so is a delete (`ENTITY_NOT_FOUND` means it is gone). An update is not sent again: the user gets a warning and the typed input stays.

**The live picture** (brief function 8; owner, 2026-10-17: the plugin must not subscribe to the viewport, which makes the object store read the whole view on every map move and sends every object in it):
- **The layers** come from one subscription with `{ objects: false }`, made at start: the layer list, the active layer and the Layer select. No objects, no counts used.
- **The selected symbol** comes from a second subscription with a small fixed area round it (a square of about 1 km half side, `areaAround` in `watch.ts`, with the symbol's position inside), made only while exactly one editable symbol is selected. It ends 2 s after the selection ends (`WATCH_GRACE_MS`; the same symbol selected again keeps it), because the map view empties the selection when it hears of a deletion and this plugin's own channel, opened later, may bring the same news a moment after: ending at once would lose the notice. An area for another symbol replaces it at once. Several selected, a shape or a track: no area.
- **The position** for the area comes from the symbol this plugin holds, or from the read by id: a symbol selected in the map view is first read (one round trip), then its area is subscribed, and the area's snapshot makes it held (live updates, drag).
- **A symbol that moved away between the read and the area's snapshot** (so it never entered and no `left` comes) is read again when the snapshot lacks it, and followed to the new place.
- **A symbol that moves out of its area** (moved by someone else, or dragged far) is reported as `area.left`: not a deletion, no notice. The read starts again and the area is subscribed again round the new position. The panel keeps showing the last state meanwhile (and the typed text stays).
- A new symbol that this browser placed is not put into the tracker: it is not selected and not in an area.
- An event for an object the plugin does not hold means "add" (it entered the area). A delete of an object it does not hold is ignored.
- If someone else changes the selected object, the panel shows it, except for a field the user is typing in (the user's commit then wins: last write wins). If it is **deleted** by someone else, the selection is cleared and a notification says so; a deletion by this same user (the shell's shared Delete) gives no notice, because the delete event says who made it (`by.user`; a delete by the same user in another browser is therefore not announced either).
- A new snapshot of the area replaces the objects. An object it lacks is treated as having left: it is not a deletion and gives no notice.

## Look (ADR-0029, ADR-0034)

- The panels use the shell's shared components (`Button`, `Select`, `TextField`, `Notice`) and its design tokens (`--emc2-*`): colours, text sizes, field height, padding, gap, corner radius and focus come from the tokens, so the three looks (Night Watch, Chart Room, Signal), light and dark, and both densities apply without a reload. `draw-symbols.css` only arranges the content; `test/tokens.test.ts` fails if a literal colour, font, size, spacing, radius or shadow appears in a checked property (the check of T-057).
- The chosen symbol in the picker is shown with Accent soft and an accent border, never a colour of the map. Place on map is the primary button; while placing it is "Stop placing".
- Icons come from Lucide (`lucide-react` 1.49.0, peer and dev dependency): Place (map pin), Stop (cross), Try again (rotate), the Edit action (pencil) and the two panels.
- The panels work in every pane (ADR-0031): the picker's grid and the identity and echelon selects wrap in a narrow pane, and the properties form takes two or more columns in the wide, low bottom pane. Checked in the real shell on 2026-10-18, see the handover.
- A grid column's minimum width is made of rows (`--emc2-size-row`), which grow with the density, so it is always capped at the container's width (`min(100%, ...)`); otherwise in comfortable density one column of the properties form is wider than the left pane and overflows it. `test/layout.test.ts` fails on an uncapped column minimum.
- **What the shared fields cannot do** (the SDK's `TextField` has no such props): the typed length is still limited in the plugin, but the SIDC field no longer has `inputMode="numeric"`, and the text fields no longer turn off `autoComplete` and `spellCheck` (the browser may underline a name or suggest earlier entries). A refused value is shown in an error `Notice` under the field (`role=alert`, so it is announced) but the input itself is no longer `aria-invalid` or linked to the message. A field that is read only without `objects.edit` is shown **disabled**, because the SDK field has no `readOnly`: it cannot be focused or its text copied (SIDC, position). These are for the SDK collection (optional `readOnly`, `inputMode`, `autoComplete`, `spellCheck` and `role="alert"` on the `error` text).

## In every workspace, and declared fields (M3, T-085)

- **Where it appears:** both panels name `workspaces: ['*']`, so they are in View, in Simulation and in any workspace a later plugin declares; the plugin never names a workspace's id. **Edit** is registered once per workspace in `ctx.workspaces` (id `edit` in View, `edit:<workspace id>` in the others), each with `workspaces: [id]` and that workspace's `editPermission` (`objects.edit` in View), so the shell offers it only where the user may edit.
- **Who may edit:** placing, editing and dragging need the workspace's edit permission (`ctx.workspace.current.editPermission`, else `objects.edit`). Without it the panels are read only with "You may not edit objects in Simulation" (View keeps "You may not edit objects"). The server checks every change anyway.
- **Where it writes:** new symbols go into the active layer, which is a layer of the workspace shown; the layer field lists that workspace's layers only (the layers subscription follows the workspace shown). **A symbol of another workspace's layer** that another plugin put into the selection is shown read only with "This symbol is not in Simulation" and is never dragged or updated.
- **On a switch** (`ctx.workspace.onChange`): the map view has cleared the selection, so the properties panel shows nothing and the symbol's area ends at once (not after the grace period: nothing was deleted). A running pick is ended by the map view with `null`, which is no Escape: the plugin drops a `null` that comes after the workspace changed. Placing, if it was on, **stays on**: it starts again in the new workspace's active layer, or waits with "Select or create a layer in the layer panel" until there is one (Stop placing still works). Nothing is asked of the map view between the shell's showing the new workspace and the switch's last step, because the layers and the active layer are not the new workspace's yet. Placing still stops for other reasons (the layer was deleted, the permission is gone).
- **Signals (CR-0020):** the pick and the drag are each started with the `signal` of an `AbortController` and ended with it when they are not wanted any more (placing stops, the active layer goes, the selection changes or ends, the object proves not to be an editable symbol in the view). What an ended interaction resolves with is not used.
- **Declared fields** (`ctx.declaredFields`, ADR-0038): the properties panel shows the symbol's declared fields under its core fields with the web SDK's `DeclaredFields` editor: the fields of the field sets the symbol carries, one set at a time (SDK 1.5.0; the group "Other fields" of SDK 1.3.0 and the group of a field's data type are gone; see "A data type brings its sets" and "Field sets, vessels and relations"); a field others may not edit is shown read only. The form starts afresh for each symbol. It commits as the core fields do (a text or number on Enter or when left, a choice and a yes/no at once, Escape drops what was typed) and sends one update with the complete core content, `baseVersion` and **only the fields the user changed** (`changeRequests.withFields`, `changedFields`; emptying a field that had a value sends `null`, emptying one that had none sends nothing, a yes/no set and cleared again sends `false`), so another user's newer value survives. A value that breaks its declaration (`fieldProblems`) is shown at its field and not sent; a refusal of the store is a notification. A value set elsewhere shows at once, except in a field the user has typed in and not committed. Fields of a plugin that is gone are not shown; their values stay on the object. With no declared fields no field is shown. Without the edit permission, or in a locked layer, the fields of the sets are shown read only (and the values of a set the symbol lacks, in that set, marked "not added").
- **Placing with fields:** the Symbols panel has the same editor under the data type (only fields with a value go with the create, with the sets added there). Its values go with each symbol placed (`withFields` on the create, checked with `fieldProblems` first: a bad value stops the click and is shown at its field), until the user changes them. They are kept in the controller, not in the panel, so a switch that mounts the panel again keeps them; they are the same in every workspace and gone after a reload. Changing the data type is described in "A data type brings its sets".
- **Look check (W3):** the CSS passes the shared `checkLookCss` (`test/tokens.test.ts`). **The W3 check (the first use of `DeclaredFields` in a browser; real shell, port 18082, 2026-10-28):** the editor in the properties panel with three fields (Team and Role as choices, Stale time as a number with its error) was measured in all 12 combinations of look (Night Watch, Chart Room, Signal), light and dark, and compact and comfortable: label contrast 5.7 to 7.6, field text 12.9 to 17.9, error text 6.1 to 6.7 and field border 5.4 to 7.2 against their background (all above 4.5 and 3), field height 26 px (compact) and 34 px (comfortable), no horizontal overflow of the editor or the pane; seen in screenshots in Night Watch dark compact, Signal light comfortable and Chart Room dark. The editor's look is the shared components' (`emc2-fields`); this plugin adds no CSS to it. In the left pane (248 and 268 px wide, compact and comfortable; Night Watch compact, Signal light and Chart Room dark) the editor is 216 and 228 px wide with no overflow, and in the bottom pane (444 px wide, comfortable) 405 px with no overflow. **Not checked:** a phone-sized window; the look of the SDK 1.3.0 group ("Other fields" and its toggle) was not measured again (T-106).

## Locked layers and the right click (M4, T-120, T-103)

- **A locked layer** (`Layer.locked`, SDK 1.3.0, ADR-0042) takes no change from a user, so the plugin treats its symbols as read only and places nothing into it. It follows the lock live, from the layers of the live picture.
- **Placing:** while the active layer is locked, "Place on map" is disabled with the title `The active layer "<name>" is locked` (the same text is the panel's status). A placing that runs when the active layer becomes locked is ended (its `pickPoint` with the `signal`) and nothing is sent. Unlocking enables the button again; placing does not start by itself.
- **Edit:** the selected symbol of a locked layer is shown in "Symbol properties" with every field read only (the declared fields too, read only) and the notice `Layer "<name>" is locked`. An unlock makes it editable; a lock while it is open makes it read only, and a value typed before is not sent (a notification says the change was not made).
- **No drag:** no `dragObject` is armed for a symbol of a locked layer, and the one armed is ended with its `signal` when the layer is locked.
- **Layer field:** the properties panel offers no locked layer as a target (the store refuses a move into it); the symbol's own layer stays in the list.
- **A refusal `LAYER_LOCKED`** (the layer was locked in between) is shown like any other refusal.
- **Right click while placing** (T-103): the map view ends `pickPoint` with `null` (SDK 1.3.0), which the plugin treats as Escape: placing switches off, nothing is created and the map is back to selecting. No code of its own; `test/lock.test.tsx` covers it with the test kit's `rightClick()`.

## Heading, speed and altitude (M4-RC2, T-130)

- **Fields:** "Symbol properties" has **Heading (°)**, **Speed** and **Altitude** right under the position, in that order, for a moving or a standing symbol. They commit as the other fields do (Enter or leaving the field, Escape drops what was typed, one update with the complete core content) and an empty field clears the value.
- **Where they are stored (SI):** the heading is the modifier `direction`, degrees clockwise from true north, 0 to under 360 (so 360 is refused); the speed is the modifier `speed` in **m/s**, 0 or more; the altitude is the point's third coordinate in **metres above the WGS84 ellipsoid** (HAE). A symbol without a value has none of them (no empty `modifiers`, no third coordinate). `cot` reads them as track `@course`, `@speed` and point `@hae`. A move of the symbol (a drag or a typed position) keeps its altitude and modifiers.
- **Units (owner's choice, 2026-11-01):** a select beside the speed field (m/s, km/h, knots, mph) and one beside the altitude field (metres, feet). They only change what is shown and typed: the stored value stays SI. The choice is kept in this browser (`localStorage` keys `draw-symbols.speedUnit` and `draw-symbols.altitudeUnit`); until the user chooses it is km/h and metres. It is **not** read from the simulator's units, which that plugin keeps under its own key. A value typed in a unit is rounded to six decimals when stored (54 km/h is 15 m/s) and shown with at most two.
- **Typing:** a number with a decimal point or comma; text that is not a number is refused with a message at its field and nothing is sent.
- **Read only** without the workspace's edit permission and in a locked layer, like every field here.

## Field sets, vessels and relations (M5, functions 27 to 29; T-132, T-139, T-150)

- **Field sets** (`ctx.fieldSets`, ADR-0050; since SDK 1.5.0 one set at a time with a menu "+", see "A data type brings its sets"): both panels give `DeclaredFields` the declared sets, the sets the symbol carries (`object.fieldSets`) and `onAddSet`. It shows the fields of the symbol's data type, one group per set the symbol carries, a read-only group for a set it lacks but has values for, and a drop-down of the declared sets with a **"+"** (grey for a set the symbol has). A set no loaded plugin declares any more is kept on the object and not shown (the SDK does both).
  - **In "Symbol properties":** the "+" adds the set at once, as a committed field does: one update, `changeRequests.withFieldSets(updateObject(...), [setId])` through the controller's `update`, which leaves out a set the object already has (two quick clicks send it once). A value set in a group commits as any declared field does (only the changed field in `fields`).
  - **In the Symbols panel:** the sets added are kept in the controller with the field values (`placeSets`, same lifetime as `placeFields`) and go with each create (`withFieldSets` on the create), those still declared. A change of data type keeps the sets and their values (ADR-0050 point 8).
  - **Read only** (no edit permission, a locked layer): no drop-down, and every field read only.
- **Vessel symbols** (`SymbolService.vesselGroups()`, ADR-0047): when the service has it, the category chooser has **Vessels** after the symbol sets. One entry per ship-type group, its picture the group's first type through `render({ standard: 'vessel', ... })` with a direction of 0 so that the hull shows, and a **Ship type** drop-down under it (default the first type; choosing a type chooses the group). The identity is the picker's, the context reality (`0`), no echelon. A vessel is placed as `{ standard: 'vessel', sidc: vesselSidc({ context: 0, identity, shipType }) }` without a direction, with the data type and placing rules of any symbol; the typed SIDC field validates with `validate('vessel', ...)`. The kept category may be Vessels; without `vesselGroups()` the picker opens on the first symbol set. "Symbol properties" shows a vessel's **Identity** (0 to 6) and **Ship type** (by name and code) instead of the SIDC's parts, and its heading and speed as for APP-6 (see above); a change writes the 4-digit code with the context it had. The setting "standard" stays APP-6's.
- **Relations and field sets go back** (ADR-0051 point 9): every update spreads the newest content, `coreOf` now includes `relations` and `fieldSets` as they came, so a rename, a move, a field or a data type change never empties the relations (model rule 5). This plugin does not show or edit relations.

## A data type brings its sets (M6, function 30; T-165; CR-0038, SDK 1.5.0 part 1)

- **The data type select** (Symbols panel and "Symbol properties") offers `choosableDataTypes(ctx.dataTypes, current)`: the types users make by hand (`manual` not `false`), so no `simulator.route`, `gmti.detection` or `gmti.platform`, and the symbol's own type in "Symbol properties" even when it is one of those, so that an edit does not change it unseen. A kept choice or the setting "Data type for new symbols" that names such a type falls back to `core.general`.
- **The type's sets at once:** `DeclaredFields` gets `dataTypes={ctx.dataTypes}` and `objectSets={withDataTypeSets(sets, type)}`: in the Symbols panel `sets` are those added there, in "Symbol properties" the symbol's. So choosing AIS vessel shows "AIS ship" before anything is placed, and a data type change shows the new type's sets. Neither a create nor an update lists the type's sets: the store adds them (model rule 21, symbols only in 1.5.0). A data type change is still one update with the new `dataType`.
- **One set at a time** (the SDK's editor): a "Field set" drop-down of the symbol's sets, opened on the data type's first set; the "+" is a menu of the declared sets the symbol lacks and is gone when none is left. In "Symbol properties" a set chosen in it is one update; in the Symbols panel it goes with each create. Read only (no permission, locked layer): no "+", the drop-down still chooses which set to see, every field read only.
- **No group for a field's `dataTypes`:** `fieldBelongsTo` is not used any more. After a data type change in the Symbols panel the values kept are those of fields in the sets the new symbols will carry (the added ones and the new type's); the others are dropped. The editor remembers the set chosen last for a data type while the page lives, so going back to a type shows that set again.
- **Expiry:** a symbol of an in plugin's type such as `ais.vessel` has no `time.observed` and does not fade (ECore); nothing to do here.

## Symbol palettes (M7, function 31; T-156; SDK 1.6.0, CR-0041 part G)

- **The drop-down "Palette"** at the top of the Symbols panel chooses what the panel offers: **General symbols** (the catalogue with its categories and Vessels, as before), then each palette of `ctx.symbolPalettes` by name, in the context's order (for example `cot`'s "CoT"). It is not shown when no plugin declares a palette. Palettes are declared in manifests only; nothing here writes one.
- **A palette's symbols** are shown in the palette's order, each drawn through the symbol service with its own standard (APP-6B codes included) and named by its `label`, else the catalogue's name for its code, else the code. A **Search** field (palettes only) keeps the symbols whose shown text contains what is typed, any case; a new palette starts with an empty search. The Category select is not shown for a palette.
- **Placing one** is placing a catalogue entry: the same data type, fields, sets and placing rules, with the palette's standard and code. **Identity and echelon apply (P1):** the panel's identity is set in the code of an APP-6D or APP-6E symbol (a code that has it already is sent exactly as the palette has it); the echelon has the extra choice "Unchanged" (the start), which leaves the code's own echelon alone, and any other choice sets it on land units only. Setting them goes through `SymbolService.describe` and `compose`, so the digits `SidcParts` does not carry (the version, the context, the sector modifiers, digits 21 to 30) get their defaults then (see the known limit). An APP-6B code is not changed.
- **Kept per user (P2):** the choice is the user document `symbol-palette` (`{ "palette": "<id>" }`, `""` for the general symbols) in `ctx.userDocuments`, so it follows the user to any browser. It is read once the panel opens, and only if the user's documents list it (reading one that does not exist answers 404, a console error on every page of a fresh user); a choice made before the read answers is not overwritten. A kept palette that is no longer offered (its plugin is not enabled) counts as General symbols. A document that cannot be read or written leaves the choice working for the page and logs a warning.
- **A code the service refuses (P3)** is shown with the error frame (a "?") and cannot be chosen; a symbol chosen whose code the service refuses after the identity or echelon changed is not placed.

## Name once, icon always (SDK 1.8.0 parts C and D; T-204)

- `plugin.json` has `"icon": "Flag"` and needs SDK `^1.8.0`. Both panels have an icon, and neither draws a heading that repeats the shell's title. **Place on map** (and **Stop placing**), which applies to the whole Symbols panel, is its `PanelFoot`, last in the body. Symbol properties commits field by field, so it has no foot.
- The settings schema has a hint of at most 80 characters for `dataType` (the only description longer than 80) and the unit `px` for `pickerSymbolSize`; three settings need no groups. The SDK's `settingsHintsProblem` finds nothing (a test names T-204).

## Settings

| Name | Default | Meaning |
|---|---|---|
| `standard` | `APP-6D` | The standard of new symbols (`APP-6D` or `APP-6E`). Also the standard a typed SIDC is checked against |
| `pickerSymbolSize` | `40` | The size of the symbol images in the picker, in pixels (16 to 128) |
| `dataType` | `core.general` | The data type of new symbols until a user has chosen one in this browser. Must be available, else `core.general` |

The settings are read when the plugin starts and again when they change (`onSettingsChange`). A bad value gives the default and the status `DEGRADED`.

## Messages and services

- Requires `emc2.map-view` (the point and drag interactions, the shared selection and the active layer; it no longer picks or selects), `emc2.symbols` (catalog, render, validate, compose, describe) and `emc2.coordinates` (format, parse, the chosen format). Provides no service.
- Uses the live picture (the layers; a small area round the selected symbol), change requests (create and update of objects; the shell's shared Delete deletes), `ctx.actions` (the object action Edit), `ctx.objects.get` (a symbol the browser does not hold), `ctx.ui.addPanel`, `ctx.user`, `ctx.dataTypes` (`onDataTypesChange`), `ctx.settings` (`onSettingsChange`), the default label, `newId()` and notifications.
- No server part, no endpoints, no topics. Status: `OK` when ready, `DEGRADED` for a bad setting, `FAILED` if a required service is not available.

## Permissions and internet

- Declares and checks the core permission `objects.edit` for create and edit (read only without it, see above); the object action Edit needs it, and the shell hides it without it. The shared Delete is the shell's and needs `objects.edit` too.
- No internet.

## Known limits

- **Setting the identity or echelon of a palette symbol rewrites the digits `SidcParts` does not carry** (as for an existing symbol's identity): only when the panel's choice differs from the code's, never for the palette's own identity or "As in the palette".
- **Identity and echelon of an existing symbol are changed with `SymbolService.describe` and `compose`.** `SidcParts` has no fields for the version digits, the context, the sector modifiers (digits 17–20) or digits 21–30, so changing the identity, echelon or entity writes the defaults for them (version 10 or 13, context 0, sector modifiers 00). Symbols made with this plugin have those values anyway; an imported symbol with others loses them on such an edit. Editing the SIDC field directly keeps what was typed. (Owner decision, 2026-10-09: a documented limit.) APP-6B symbols, vessel symbols (the standard `vessel` of SDK 1.4.0) and SIDCs the service cannot describe have no identity, echelon and entity choices, only the SIDC field.
- **A snapshot that lacks the watched object gives no notice.** In area mode a missing object may have been deleted or may only be outside the area, and the plugin cannot tell; the panel shows what is read from the server (or "The selected object no longer exists."). A deletion that happened while the connection was down is therefore not announced. A delete event for the object is announced.
- **A drag that ends with null is not asked for again at once.** `dragObject` resolves null on Escape, when another interaction replaces it, and at once for an object the map does not draw. The plugin asks again only when the selection changes, the selected symbol itself changes or arrives, the view moves or a layer is shown or hidden (T-054; not for an object that is not known yet: its early drag is armed once per selection, T-066); before, a selected symbol the map did not draw made it ask thousands of times a second. Limits: the layer trigger works once the map view reports layer visibility (it passes no listener yet, `TODO(T-054)`); and if this plugin hears of a selected symbol before the map view holds it, the drag waits for the next view move or selection (the plugin and the map view keep separate copies of the live picture).
- **The plugin ends a pick and a drag with their `signal`s** (SDK 1.2.0, CR-0020; T-066 for the drag, T-085 for the pick): each armed interaction has an `AbortController`, ended when it is not wanted any more (placing stops, the active layer goes, the selection changes or ends, the object proves not to be an editable symbol in the view), and an abort does not clear the selection. What an ended interaction resolves with is not used; a `null` that comes after the workspace changed is the switch's, not Escape. The plugin assumes that a later call replaces an earlier one and that a drag can be started again after each drop. This works with `map-view-2d` (checked in the browser on 2026-10-10: select, drag, Escape, Delete).
- **The double-click time is a constant** (`DOUBLE_CLICK_MS`, 250 ms: OpenLayers' double-click time in the version shipped, ol 10.10.0, which is the time the map view uses; owner decision of 2026-10-10, brief criterion 10), not a setting and not read from the operating system. The map view's own double-click zoom has to be off while placing (`map-view-2d`); this plugin only merges the clicks.
- **The deletion notice** ("The selected symbol was deleted by someone else.") is keyed off this plugin's own record of the selected symbol and its own tracker, because the map view also removes a deleted object from the selection, possibly just before this plugin hears of it. The record is kept for 2 s after the selection became empty or several (`WATCH_GRACE_MS`), then forgotten: a symbol the user deselected is announced only if it is deleted within those 2 s. If the delete event reaches this plugin later than that, the notice is missed (never a false one). Whether the real server delivers the map view's and this plugin's channel in this order is not measured (in the no-login mode every user is `local`, so no notice shows in a browser check). Only a `core.symbol` is announced; a shape or a track has its own plugin. In the no-login mode every user is `local`, so a deletion by anyone counts as the user's own and is never announced.
- **The plugin reads by id any single selected object it does not hold**, before it knows the object's type: for a shape or track outside the area the panel may briefly say "The selected object has not arrived yet.", or "Could not read the symbol, try again." if the read fails, and then shows nothing for it.
- **Every selection by the map view waits for one read and one subscription** before the panel fills (the plugin holds no objects of its own). While the selected symbol moves out of its area, the area follows it with a read and a new subscription; the area is about 2 km wide, so a symbol dragged across the map is followed again for every move out of it.
- **The drag armed before the object is known is a press that might not be a symbol's (T-066).** It stays armed until the read answers, one round trip, and then ends if the object is not an editable symbol in the view. In that window a press on a selected shape grabs it for this plugin's drag (the map does not pan there, a preview follows the pointer) and its drop is ignored; `draw-shapes`' drag, armed once it knows the shape, replaces it, and the next press moves the shape. It is armed once per selection: a selection made while placing does not arm it (the placing ends when another plugin's drag starts, as Escape ends it, owner's (b), 2026-10-27), and a read that failed and is tried again does not arm it a second time. So after a drop made before the read answered, or when placing is stopped by hand while such a selection is open, the next press has no drag until the read answers (one round trip). The arming still ends another plugin's running `draw`, `edit` or `pickPoint` when the selection changes during it (it already did so for held symbols in view). Also: each selection of an object the map view does not hold (Edit from `object-list` for a far symbol, a hidden layer) makes the map view log "dragObject: the object is not on the map" once.
- **Escape** is the map view's: it ends `pickPoint` with null (the plugin then stops placing) and clears the selection. The plugin has no key handler.
- **The kept data type belongs to one browser profile** (`localStorage`). It is lost when site data is cleared, and then the setting applies. If storage is blocked, the choice lasts until the page is reloaded.
- **Expiry** (model rule 15) is not shown in the properties panel; the map view fades expired objects.
- **The picker offers every standard identity of the catalog**, not only friend, hostile, neutral and unknown. A vessel has the identities 0 to 6 (APP-6D's digits), so a catalog identity outside them gives no vessel ("This combination of parts cannot be composed."), and the properties panel offers a vessel only those.
- **A vessel's context is reality in the picker.** The properties panel keeps the context a stored vessel has (exercise, simulation) and changes only its identity and ship type. The group's picture uses the group's first ship type (the colour is the group's); the symbol placed has the type chosen.
- **A field in no field set is not shown.** The editor shows fields through sets only (SDK 1.5.0), so a declared field that no set lists is neither shown nor editable here.
- **A refused select** (identity, echelon, entity, layer, data type) shows the server's value again after the notification; only text fields keep the user's input.
- **Typing a position:** the conversions belong to the `coordinates` plugin. The tests here use a double that knows a few texts for DD, DMS and MGRS, and the test kit's coordinate service, and check that the position `CoordinateService.parse` returns is sent unchanged, as lon/lat, and that the position is shown through `format`. A parse error is shown and nothing is sent.
- **Not covered by the unit tests** (jsdom has no canvas and no map): real pixels of the symbol images, the drop point within 1 pixel of the pointer (criterion 3), and a symbol appearing in a second browser within 1 s (criterion 1). These are for the ITA's browser tests. The tests check that the drop point is sent unchanged and that a second fake browser receives the change.
- A new symbol has no altitude. An object that has one keeps it when moved.
- The web build needs the shell's import map, so build the shell first (`npm run build --workspaces` at the repository root does).
