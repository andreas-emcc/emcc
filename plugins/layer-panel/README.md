# layer-panel

The Photoshop-like layer list (brief: `docs/plugins/briefs/layer-panel.md`; tasks T-024, T-042 for M1, T-054 for M2, T-085 for M3, T-108 and T-099 for M4, T-171 and T-154 for M6, and T-204 for M8). Web part only, built against SDK 1.8.0 (`sdkVersion` `^1.8.0`; T-204: the manifest's `icon` `Layers`, the same Lucide icon as the panel's, and no inner heading repeating the title; no settings, so no settings hints; "New layer" is the list's own action and stays at the top of the body, not in a `PanelFoot`).

## What it does

A panel **"Layers"** (panel id `layer-panel`, with the Lucide `Layers` icon). It starts in the **bottom pane**, next to `object-list`'s "Objects" (from M4, BS; the left pane before), and the user may move it to the left or the right pane (`addPanel`, ADR-0031); it works in each. **From M3 it is in every workspace** (`workspaces: ['*']`) and lists the layers of the workspace shown (ADR-0039; the workspace rules in `docs/plugins/briefs/README.md`).

- **Workspaces (M3):**
  - its subscription names no workspace, so it follows the one shown: on a switch the list shows the new workspace's layers and counts from the fresh snapshot;
  - "New layer" and "Create first layer" create the layer in the workspace shown (`workspace` set to its id; in View none), and "Layer N" counts that workspace's layers;
  - an update carries the layer's own `workspace` as stored, or none for a View layer;
  - reorder moves a layer among that workspace's layers only, and a renumbering touches only them;
  - **View's layers as a reference:** in a declared workspace (e.g. Simulation) a second group, "View (reference)", under the workspace's own layers, from a second subscription `{ objects: false, workspaces: ['core.view'] }` held only while such a workspace is shown. Each row has the name, the classification, the count and the eye; no active marker, no rename, move or delete, and a click, Space, a double-click and Enter do nothing. Its eye is the layer's visibility in the workspace shown, which the map view keeps per workspace and starts off (`map-view-2d` function 23); the panel only shows and toggles it. With no View layers it says "No layers in View".
- Lists the layers, the top of the draw order first: higher `drawOrder` on top, ties broken by the higher id on top. Each row shows the eye, the lock, the name and the buttons, and under them the classification of the layer's label and the number of objects. Where the name would get less than 30 % of the row (a narrow pane in the comfortable density), the buttons wrap to a line of their own under the name. The active layer is shown as a selected row. Layers created by other plugins (e.g. one per `cot` stream) are listed and handled like any other.
- **Counts:** the number of objects per layer is the server's count over the whole picture (`snapshot.objectCounts`, then every `counts` update), not of the map view. The panel receives no objects (brief, function 11).
- **Reorder** by drag and drop (grab the row anywhere, also by its name) or with the ▲/▼ buttons. A move sends one update for the moved layer only, with the midpoint between its new neighbours as `drawOrder` (one more than the top, one less than the bottom). If no number fits strictly between the neighbours (floating-point limit, equal values), all layers are renumbered 0…n−1 in the new order, one update per layer whose value changes.
- **Eye:** hides or shows the layer in this browser only (`MapView.setLayerVisible`). It sends nothing and never changes the shared `visible` field. The eyes follow `MapView.onLayerVisibilityChange`, so they change at once when the map view restores a setup; the map view saves the visibility in its setup share, the panel keeps none.
- **Opening a layer's objects (M2):** a **double-click anywhere on a row** opens `object-list` for that layer (`OBJECT_LIST.open`), also for a hidden layer and without `layers.edit`; so does **Enter** on the name (owner, 2026-10-17). A double-click on the row's buttons or in the name field does not. Without `object-list` both do nothing, and no tooltip mentions them.
- **Active layer:** a click anywhere on a row (not on its buttons), or Space on the name, makes the layer active (`MapView.activeLayer`), where `draw-symbols` and `draw-shapes` place new objects. It is always one of the workspace's own layers, at any time (brief, function 21): if a change deletes the active layer, the next one down becomes active, or the top layer when it was the bottom one; when it is none, or any id the list does not hold (another workspace's layer, a reference layer, an unknown id, or one a fresh snapshot no longer has), the top layer becomes active; with no layers, none. So on a switch a layer the map view brings back stands, and the top layer only fills a gap, in whatever order the plugins' `onChange` listeners run.
- **New layer:** "New layer" and "Create first layer" open the shared dialog "New layer" (M6, function 23): a "Name" field with "Layer N" (N one more than the highest number in a name of that form), and a "Classification" select with the default policy's order, lowest first (`ctx.classifications`, matched ignoring case), the default classification chosen. Create sends one create, on top, visible, with the default label but the chosen classification (labels are cosmetic in M6); Cancel and Escape send nothing. Without an order (no `ctx.classifications`, none for the policy, or the default classification outside it) there is no select and the layer gets the default label. The shared dialog cannot disable Create, so Create with an empty name sends nothing, keeps the dialog open and shows "Enter a name" under the field (owner, 2026-11-11). The new layer becomes active once the live picture lists it (owner, 2026-10-27); if the user makes another layer active meanwhile, that choice stands.
- **The active layer over the map (M6, function 24):** a Map Pane overlay at the bottom left (order 110, just above `coordinates`' cursor display), in every workspace, framed as an icon over the map: "Active layer: <name>", with Lucide `Lock` ("Locked") before the name of a locked layer, or "No active layer". It follows the panel's own state at once (the active layer, a rename, a lock, a delete). One line of small text, at most 40 % of the Map Pane's width (measured, since the shell's overlay column is as wide as its content); a longer name ends with "…" and shows whole in the tooltip. It only shows: no button and no tab stop. Without a map view there is no overlay.
- **Lock (M4, function 22; ADR-0042):** the lock beside the eye is the layer's stored `locked`, one value for every user and browser, and follows the live picture. A click sends one layer update with the complete content, `baseVersion` and `locked: true` or `false`; a rename or a move leaves `locked` out, so the stored lock stays. On a locked row Rename (✎ and F2) and Delete are disabled with the tooltip "The layer is locked"; moving it (▲ ▼ and drag), the eye and making it active still work, since the server takes a draw-order change. Without the permission to change the layer the lock shows its state, disabled, with the tooltip "You may not change this layer". A `LAYER_LOCKED` rejection (another user locked the layer in between) is a notification with the layer's name. The reference group has no lock.
- **Rename:** F2 on the name, or ✎ (from M2 no longer a double-click, which opens `object-list`). The old name starts selected. Enter or leaving the field commits, Escape cancels. An empty or unchanged name sends nothing.
- **Delete:** only empty layers by the server's counts, after a confirmation in the shared dialog ("Delete layer", Cancel focused). The button is disabled, with the reason as its tooltip, while the layer has objects.
- **Without `layers.edit`** in View, or the workspace's `editPermission` elsewhere (`plugin.simulator.edit` in Simulation; brief, functions 10 and 18): the panel is read only, with the hint "You may not change layers" in View and "You may not change layers in Simulation" in Simulation (the workspace's name; owner, 2026-10-27). "New layer" and "Create first layer" are disabled and say so; the row buttons ▲ ▼ ✎ ✕ stay visible but disabled, with the hint as tooltip; rows cannot be dragged, and F2 does not rename. The list, the counts, the eye, the active layer and opening `object-list` work as always. The controller also refuses these actions itself, so nothing is sent.
- Every update sends the complete layer content (`name`, `drawOrder`, `visible`, `label`, and `extensions` forwarded untouched) with `baseVersion`. The list only follows the live picture; nothing is changed locally before the server applies it.
- Rejections (e.g. `LAYER_NOT_EMPTY` when an object was added meanwhile) are shown as error notifications; `PERMISSION_DENIED` says the hint of the workspace shown with the server's reason. A lost answer (`OutcomeUnknownError`) is shown as a warning. Nothing is retried.
- **One action of a kind at a time:** a create, a rename, move or lock, or the delete of one layer is refused while the same kind is still on its way, from the click until the live picture shows the applied change (or it was rejected or lost; at most 5 s). So a double click sends one request, and no rename or move is computed from content the server has already changed. Meanwhile "New layer", the move buttons and that layer's Delete are disabled; a rename refused this way says so in a notification, and a drop is ignored.
- **Look (M2, ADR-0029, ADR-0034):** the panel follows the user's look, light or dark, and density. Its CSS uses design tokens only. It is built from the shared `Button`, `IconButton`, `Notice`, `ConfirmDialog`, `TextField`, `Select` and `Icon`, with Lucide icons. The row buttons (the eye, the lock, ▲ ▼ ✎ ✕) are `IconButton`s with a tooltip apart from their name (CR-0024, SDK 1.2.0). "New layer" stays at the top while the list scrolls. The CSS is checked with the test kit's `checkLookCss`.
- **Errors:** an unexpected error in an action is logged and shown as a notification (if that fails too, it goes to the browser console, and the action still ends); a rendering error is caught inside the panel, logged, and shown with a "Try again" button.

## Settings

None.

## Messages and services

- Provides: the panel "Layers" (default pane: bottom; every workspace), and from M6 the Map Pane overlay with the active layer (bottom left, every workspace). No services.
- Requires: `emc2.map-view` (`MapView`: active layer, local visibility and its change event). Without it the status is `DEGRADED` and the list, reorder, create, rename and delete still work; the eye and the active layer do not.
- Uses (`uses`, CR-0011): `emc2.object-list` (`ObjectListService.open`). Without it (not installed, failed or disabled) the status stays `OK`, with the detail "object-list not available: double-click opens nothing", and the panel works as before.
- Uses: the live picture subscription with `{ objects: false }` (layers, layer events and the server's object counts per layer; no objects), and in a declared workspace a second one with `workspaces: ['core.view']`; change requests for layers (create, update, delete), the default label, `ctx.user` (permissions), `ctx.workspace` (the workspace shown and its switch), notifications.
- No server part, no endpoints, no topics.

## Permissions and internet

- Checks `layers.edit` (core) in View, and a declared workspace's `editPermission` there, for create, rename, reorder and delete, through `ctx.user` (ADR-0022, ADR-0039 point 7); the server checks it too. `plugin.json` lists `layers.edit` as the core permission it checks; it declares none of its own. In the no-login mode the local user has every permission. Visibility and the active layer are local and always allowed.
- No internet.

## Known limits

- A renumbering sends one update per changed layer. They are not atomic: if some are rejected, the order can be partly renumbered until the user moves again.
- A create and a move that are on their way at the same time can give two layers the same `drawOrder`. That is a valid state: the tie is broken by id, the same way in every browser, and the next move between them renumbers.
- The web build needs the shell's import map: build the shell first (design pattern, FAQ).
- The user's permissions are fixed for the session (ADR-0022); which one applies follows the workspace shown.
