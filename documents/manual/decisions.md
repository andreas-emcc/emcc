# The manual: choices made and open questions

Written by the UDA on 2026-11-03/04, while the owner slept. The owner asked for the whole manual to be written in one go, with every choice recorded so that it can be redone question by question. Each entry has the question, what I chose, what else could have been chosen, and where in the manual it shows. "Check" means: not walked through in the running release, or a guess; look at it first when you review.

## How the manual was made

**Q1. How are the screenshots taken?**
- Chosen: with Playwright (`playwright-core` 1.63.0, the version the ITA pins; Apache-2.0), by `documents/manual/src/shots.mjs`, in Playwright's own Chromium. The owner said yes to trying it on 2026-11-03.
- Why: the browser pane scaled screenshots to about 0.6, too small for a manual, and a script can be run again for the next release.
- Else: the browser pane in a narrow window; the owner's own screenshots.
- Open: `agents/uda.md` rule 2 still says "from the browser pane". The ACA should change it. Also `playwright-core` is a new dependency of `documents/manual/src/package.json`; it is covered by CR-0036's reasoning only for licence (Apache-2.0 is on the list), so no new licence is needed.

**Q2. One look and theme for all screenshots.**
- Chosen: the installation default (Night Watch), light, because a light manual prints better. Natural Earth is the background.
- Else: dark; Chart Room (made for daylight and projectors). To change: `colorScheme` and a Look step at the top of `shots.mjs`, then run it again.

**Q3. Screenshot size.** 1336 × 849 at scale 1, PNG, panes and menus cropped. Else: twice the scale for sharper text on print.

**Q4. The script checks the manual.** Each step asserts what the chapter says, so a changed release fails the script instead of giving a wrong picture. The run needs a freshly started emcc (it places objects and makes a bookmark and setup).

**Q5. The built HTML is not committed** (owner, 2026-11-03).

## Structure

**Q6. Part 1 holds the running of emcc and the permissions,** not only the product and the plugins, and a "first session" chapter follows the interface overview in part 2. Else: an installation guide as its own part.

**Q7. Part 1 is for operators and admins.** "The plugins" says what each plugin gives you and where it is described. It leaves out how plugins are made. Adding or removing a plugin is not described, because I did not find an operator procedure: check with the MCA (`tools/release.mjs`) if there is one.

**Q8. Part 4 does not repeat the panels it shares with View.** It describes only what differs, and links to part 3. Else: a full chapter per panel in each workspace, as in the owner's first wording ("the same structure as the view chapter"). The Simulation chapters are: the workspace, Routes, Route editor (with the Event panel inside it) and Outputs.

**Q9. Part 5 has one chapter per settings category** (17), named as the Settings list names them, written from the settings' own descriptions in the running release, so they match what the admin sees. The defaults come from there too.

**Q10. The monitor is one chapter.** The owner asked for a short description.

**Q11. Appendices:** mouse and keys, known limits and troubleshooting, glossary.
