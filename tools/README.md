# tools/

Build and development scripts, owned by the MCA. Plain Node.js (no dependencies), so they work the same on Windows and Linux. Run them from anywhere in the repository.

| Command | What it does |
|---|---|
| `node tools/build.mjs` | Builds `server/` (Maven, tests skipped) and the web client and plugin web parts (npm workspaces at the repository root, CR-0006), then assembles the installed layout of every plugin into `build/plugins/<id>/` (`tools/assemble-plugins.mjs`, `docs/plugins/design-pattern.md` section 4): `plugin.json`, `server/*.jar`, `web/`. Folders starting with `_` (the template) are skipped. A plugin whose id differs from its folder name, or that lacks a built part its manifest declares, fails the build. Finally it writes the third-party notices (`tools/notices.mjs`). |
| `node tools/test.mjs` | Runs all unit tests in `server/` (`mvn verify`), `web/` (`npm test` in every workspace), the data model tests in `model/` (`npm ci`, then `npm test`) and the tests of these tools (`node --test tools/*.test.mjs`). |
| `node tools/licenses.mjs` | Checks dependency licenses against `CLAUDE.md` section 4 and ADR-0016: npm lock files (`web/`, `model/`) and the libraries inside the built server jar (build first). Fails on a license the policy does not allow, warns when license information is missing. Needs nothing installed. |
| `node tools/notices.mjs` | Writes `build/THIRD-PARTY-NOTICES.txt` (T-028): the licence and copyright texts of every shipped dependency, collected from disk (npm packages the root lock file does not mark `dev`, and the libraries inside the server jar). A package without a text gets the standard text of its licence (Apache-2.0, EPL-2.0), marked as added with the copyright holder and source from its metadata. Fails when a shipped package has no text and none can be added. Run by the build; needs the built server jar. |
| `node tools/release.mjs` | Builds everything, then a self-contained zip in `releases/` (ignored by git): `emcc-<milestone>-<date>-<commit>-<os>-<arch>.zip` (the product name, T-134; `--milestone` names the milestone) with the server jar, the web client, the installed plugins, a Java runtime made with `jlink` from `JAVA_HOME` (CR-0008) and `start.bat [port]` (`start.sh` on Linux). Unpack and run it on a machine without Java. The zip also contains `THIRD-PARTY-NOTICES.txt` and the project's `LICENSE`. When `documents/manual/src/` exists, the user manual is built there (`npm ci --offline`, `npm run build`) and ships in `manual/` (T-145). The start scripts stop when the zip is not unpacked, warn about `application-local.properties.txt` and print the folder they read the settings from (T-146). The runtime is native: build on the platform you ship to. `--skip-build` uses the current build. |
| `node tools/overview.mjs` | Generates `tools/out/project-overview.html`: where we are, next steps per agent, all tasks, spikes, change requests and ADRs, open and closed. Reads `docs/` and git; the output is not committed. On Windows, double-click `tools/overview.bat` instead: it finds Node.js even when it is not on the PATH, generates the page and opens it. |
| `node tools/start.mjs` | Starts the built system locally with the no-login `dev` profile and the assembled plugins from `build/plugins/`. |

Requirements: Node.js, npm, and (for `server/`) JDK 25 and Maven on the `PATH`.

A part that does not exist yet (`server/pom.xml`, the root `package.json`) is skipped. Integration tests (`tests/integration/`) are run by the ITA. The start script's launcher path and profile name are placeholders until the CDA delivers `server/app/` (T-010).
